# 第6章：AI活用ガードレール（機密/再現性/レビュー）

## この章で学ぶこと

- AI出力は“仮説”として扱い、一次情報/検証で裏取りする
- 機密情報を入力しない（入力制御と手順）
- レビュー観点（前提/例外/互換性）で品質を担保する

## 成果物（または判断基準）

- AI利用チェック（付録: [AI利用チェック](../../appendices/checklists/)）
- AI出力の検証メモ（何を裏取りしたか）
- AI出力の採用/不採用理由（一次情報または検証との対応）

## 本文

AIは検索の代替ではなく、調査の加速装置として位置付ける。出力の正しさは保証されないため、必ず裏取りが必要。

### 手順（最小）

1. AIに渡す前に、目的と制約（機密/対象バージョン/環境）を整理する
2. 入力は最小化し、秘密情報/個人情報/顧客情報を含めない
3. 出力は仮説として分解し、一次情報（公式/仕様/実装）と検証で裏取りする
4. 採用/不採用の判断と根拠を調査ログに残す（再現性と監査性を担保する）

### 実務でのガードレール

- 入力: 秘密情報/個人情報/顧客情報を投入しない
- 出力: 仕様/実装/検証で裏取りする
- 共有: 結論だけでなく“根拠”を残す
- レビュー: 前提/例外/互換性/影響をチェックする

### AI出力の採否判定

AI出力は「根拠」ではなく「候補」である。採用するには、根拠タイプと検証状態を明示する。

|AIの用途|採用前に必要な確認|記録すること|
|---|---|---|
|検索クエリや観点出し|一次情報への導線として妥当か|採用したクエリ、捨てたクエリ|
|仕様の要約|原文の対象版・該当節と一致するか|原文リンク、要約、差分、未確定点|
|コードやコマンド案|安全性、対象環境、最小構成での実行結果|実行環境、ログ、失敗時の扱い|
|引用・リンク候補|リンクが実在し、該当箇所が存在するか|確認日、該当見出し、採用/不採用|
|判断文・PR説明|実際の変更内容、検証結果、リスクと一致するか|人間が確認した最終文責者|

採用できない例:

- AIが提示したリンクや引用を、実在確認せずに PR body や Issue に貼る
- AIが生成したコマンドを、本番環境や共有環境で直接実行する
- 「多くの場合」「一般に」などの表現を、対象バージョンや制約なしに結論へ使う
- セキュリティ、法務、プライバシー、費用、SLA に関わる判断を AI出力だけで確定する

### 注意点

- 生成AIは「それらしいが誤り」の出力を返しうる。引用・リンク・数値は一次情報で要確認とする
- 入力の取り扱い（保持/学習/共有範囲）は提供形態で異なる。組織の規程に従う（不明な場合は要確認）

#### ミニ例（ログ→仮説→裏取り）

入力（マスキング済み）:

```text
error=TimeoutError elapsed=10.02s
x-request-id=2f3a8d1c-...
```

プロンプト例:

```text
次のログから原因候補を3つ挙げ、各候補について一次情報/検証での裏取り手順を1つずつ提案してください。
不明な点は推測で断定せず「不明」と書き、追加で必要な情報（例: 対象ライブラリのバージョン、設定値、リトライ有無）も列挙してください。
```

## 具体例（悪い例→良い例）

### 悪い例

```md
AIの回答をそのまま採用して実装
根拠は残さず、検証もしていない
```

### 良い例

```md
AIの回答を仮説として整理
一次情報: 公式ドキュメント/仕様/実装で裏取り
検証: 最小構成で再現
共有: 調査ログに結論/根拠/未確定点を記録
```

## チェックリスト

- [ ] 機密情報を入力していない
- [ ] 一次情報または検証で裏取りした
- [ ] AIが提示したリンク、引用、数値を実在確認した
- [ ] AIが提示したコード/コマンドは、安全性・対象環境・最小構成での実行結果を確認した
- [ ] 前提/例外/互換性を確認した
- [ ] 根拠を調査ログに残した
- [ ] 採用/不採用理由と最終文責者を記録した

## まとめ

- AI出力は仮説として扱い、一次情報/検証で裏取りする
- 入力制御（機密/個人情報）とレビュー観点で安全性・再現性を担保する
- AIが提示したリンク、引用、数値は実在確認し、コード/コマンドは安全性と動作確認のログが揃うまで採用しない
